# 0006. Page Price Detection and Scanning

Date: 2026-03-01
Status: Accepted

## Context
Web pages render prices in diverse formats: single text nodes, nested inline spans (e.g. currency symbol, whole number, and fractional superscript on e-commerce sites like Amazon), European comma-decimals (`149,50 €`), and dynamic single-page application (SPA) updates. The scanner must detect prices accurately without breaking interactive inputs, code snippets, or causing infinite mutation loops.

## Decision
Implement a two-phase DOM scanner in `PageScanner`:
1. **Text Node Scanning**: Traverses light and shadow DOM using `TreeWalker`, filtering against blacklisted tags (`script`, `style`, `noscript`, `textarea`, `input`, `select`, `option`, `code`, `pre`, `svg`, `canvas`, `[contenteditable]`, `[data-cc-ignore]`).
2. **Split-Price Element Assembly**: Identifies elements where `textContent.length < 40` matches a valid price pattern spread across child tags (such as Amazon product blocks). Wraps or replaces them as a cohesive unit and stores original child fragments in a `WeakMap<Element, DocumentFragment>` for byte-for-byte revert fidelity.
3. **Batching & Idle Execution**: DOM tree walking runs in chunks (~200 nodes) with `requestIdleCallback` (with `setTimeout` fallback).
4. **MutationObserver**: Debounced by ~150ms. Ignores mutations generated by the extension's own operations via data attributes to prevent infinite loops.

## Rationale
- High precision: Handles complex modern e-commerce markup without mangling layout.
- Non-blocking: Idle batching prevents UI freezing or dropped frames during initial scans.
- 100% reversible: `revert()` restores original text nodes and split-element fragments identically.

## Consequences
- Requires maintaining the `WeakMap` metadata during the lifecycle of the converted page.
